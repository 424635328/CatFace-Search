# 标签碰撞：同一张照片出现在两个身份标签下

**结论先说**：这份语料里**有 137 对"同一张照片、不同身份标签"的图**，分布在 5 组标签之间。
它让发布的 `hit@1 = 0.9682` **低估了模型**：503 个查询里有 5 个之所以被判错，是因为它检索到的
top-1 就是**它自己的照片**，只是那张照片挂在另一个身份标签下。剔除这 5 个标注缺陷后是
**0.9781**。

这不是模型问题，是数据标注问题。但报告必须两件事都写清楚，否则读者会以为 16 个错误全是模型的。

## 怎么发现的

给 `tools/find_best_match.py` 排名"识别最可靠的那张图"时，"最自信"那一栏的第一名让事情变得很可疑：

| | 值 |
|---|---|
| 查询 | `cat_individuals__0077_0077_031.JPG.jpg`（标签 `0077`）|
| top-1 | `cat_individuals__0083_0083_024.JPG.jpg`（标签 `0083`）|
| 余弦相似度 | **0.9999992** |
| 判定 | **错**（标签不同）|

两张不同猫的照片不可能有 0.9999992 的余弦相似度。于是不看嵌入、直接比像素：

| 对比 | 最大像素差 | 平均像素差 | 不同像素占比 |
|---|---|---|---|
| `0077_031` vs `0083_024` | **6** | 0.0178 | 1.77 % |
| 对照组：两张真正不同的猫 | 238 | 67.44 | 100 % |

最大差 6、只有 1.77 % 的像素变了——这是**同一张图被重新编码（re-encode）**的特征，不是两只猫。

## 量化

`tools/find_duplicates.py`：用嵌入相似度（阈值 0.98）**只做粗筛**，再用**像素比对**逐一确认，
因为单看嵌入无法区分"模型弄混了"和"文件本来就是同一张"。12644 张图、粗筛 185 对：

| 标签对 | 已确认同一张照片的对数 |
|---|---|
| `0455` vs `0455_357` | 87 |
| `0077` vs `0083` | 30 |
| `0046` vs `0082` | 17 |
| `0314` vs `0317` | 2 |
| `0335` vs `0337` | 1 |
| **合计** | **137** |

涉及 10 个标签。原始数据在 `docs/diagnostics/cross-identity-duplicates.json`。

### 成因

`0455_357` 是 `0455` 目录下的**子文件夹**，而不是独立的一级文件夹：

```
cat_individuals_dataset/
    0455/            714 张
        0455_357/    （子目录，同样属于 0455 这只猫）
```

Kaggle 这份 `timost1234/cat-individuals` 语料对同一只猫用了两套命名（`NNNN` 与 `NNNN_MMM`），
本项目按文件夹名当身份拆分，于是把同一只猫当成了两只。`0077`/`0083`、`0046`/`0082` 等组合同理。

**所以 503 个"身份"里有 5 组其实是同一只猫，真实个体数约 498。**

## 对指标的影响

对 503 个查询中判错的 16 个逐一归因：

| 类别 | 个数 | 说明 |
|---|---|---|
| **标注缺陷**（top-1 是查询自身的同一张照片，只是标签不同）| **5** | 相似度 0.9994–0.9999，模型其实是对的 |
| 真正的模型错误（top-1 是另一张照片）| 11 | 相似度 0.44–0.67，且 margin 为负，属于难样本 |

| 口径 | hit@1 |
|---|---|
| 按发布口径（标签为准）| 0.9682 |
| 剔除 5 个标注缺陷后 | **0.9781** |

这个方向是**低估**。反方向的风险也在同一批数据里：如果同一只猫的两个标签分别进了 query 和
gallery，那这个查询就变得过于容易。本项目按**标签**做身份不相交划分，而 5 组碰撞标签共享照片，
因此 `assert_identity_disjoint` 这类按标签的检查看不到这个问题——**它检查的是标签，不是照片**。

## 复现命令

```powershell
# 排名：哪张图识别最可靠 / 最自信 / 最不可靠
python -m tools.find_best_match --checkpoint artifacts/train/dinov2s-arcface/best.pt --top 10

# 找出跨身份标签的重复照片（先粗筛再像素验证）
python -m tools.find_duplicates --checkpoint artifacts/train/dinov2s-arcface/best.pt
```

## 该怎么用这个结果

1. **报告两个数**：`0.9682`（标签口径，可直接与其它论文对比）和 `0.9781`（剔除标注缺陷）。不要只报后者，
   那等于把数据缺陷当成自己的功劳。
2. **不要用这份语料做"个体数"统计**：503 是标签数，不是猫的数量。
3. **换语料时要先跑 `find_duplicates`**：跨标签重复是这类"按文件夹名当标签"的爬取语料的通病，
   而它同时会造成低估（自己检索到自己却被判错）和高估（同一只猫跨 split）。
